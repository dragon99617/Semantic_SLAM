## 固定评测范围与口径

- M2DGR：door_02、door_01，使用现有 FAST-LIVO2 ROS 2 移植版。核对图像/LiDAR/IMU 与标定、时间、测量参考点后，计算全程平移 APE、适用的 RPE、有效真值覆盖和运行完整性。转场窗口需要独立标注；不将视觉里程计退化直接当作语义地图质量结论。
- Replica：以 OVO 官方实现作为语义基线，起步场景 room0、office0、office1。使用公开数据与官方语义标注，固定参考位姿隔离语义映射，报告 3D 语义 IoU/准确率、覆盖、时间和资源开销。该设置不是 FAST-LIVO2 端到端定位评测。
- OSMa-Bench：以同一语义基线评测三个布局 v3_sc0_staging_00、v3_sc1_staging_00、v3_sc2_staging_00。先审计公开数据实际提供的光照配置，再报告可运行的原生条件；缺失条件不能冒充已完成，人工亮度扰动必须单独标为附加实验。
- 尚未实现的新可靠性机制、CLIP 之外的历史图像复核或导航模块，不报告虚构的改进/任务指标。

## 环境和资料

- WSL2 Ubuntu 22.04，系统 RAM 约 7.6 GiB、swap 2 GiB，RTX 4060 8 GiB，当前磁盘空间充足。
- ROS 2 环境保持原样；语义依赖安装到单独的 `third_party/semantic_venv/`，使用项目目录中的 Python 3.11。
- 官方 OVO、OSMa-Bench、M2DGR 源码已克隆；提交号在 `source_versions.json`。
- Replica 采用 OVO 官方数据说明指定的 NICE-SLAM 预处理数据；OSMa-Bench 采用发布方 Hugging Face 压缩包。
- OSMa-Bench 的 `data.zip` 为 3,218,010,116 字节，SHA-256 与发布方 LFS 哈希一致；已解压并通过 ZIP CRC 校验。数据来源记录在 `datasets/OSMa-Bench_original/provenance.json`。
- OVO 当前默认是 SAM2.1 + SigLIP-384 + 作者学习的视图融合权重。为控制 8 GiB 显存/系统内存，准备固定半精度、图像小批处理及无副本权重加载；任何与默认配置不同的设置都会记录，不声称复现原论文全套精度。

## 最终复核与结论

- 发布数据：Replica 场景平均 mIoU/mAcc 为 25.34% / 35.55%；OSMa 三个 baseline 布局为 27.21% / 42.82%。
- 本地配对：baseline 27.69% mIoU；camera_lights 29.82%；no_lights 24.47%；dynamic_lights 24.04%。动态灯光相对其本地 baseline 下降 3.65 个百分点。
- `paired_data_checks.json`：12/12 数据组帧数、哈希、相同位姿/内参/类别、共享深度/真值和真实 RGB 变化检查通过。
- `final_result_checks.json`：18/18 结果由逐点预测和原始 GT 独立复建混淆矩阵、使用官方函数复算指标；Replica 抽样最近邻实例投票与官方实现一致。
- 这些结果是使用参考位姿的语义基线及受控光照实验；没有声称 FAST-LIVO2 在这些 RGB-D 场景上完成端到端定位，未实现的可靠性机制/复核/导航仍未作改进对照。
- M2DGR 无有效 bag/GT，本次未产生其精度结果，不将它列入完成项。
