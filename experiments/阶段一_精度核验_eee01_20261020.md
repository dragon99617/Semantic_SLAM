# 第一阶段补充：NTU-VIRAL eee_01 精度核验

完成日期：2026-10-20。**已完成一条有测量真值的公开序列精度核验。本地 ROS 2 移植版平移 APE RMSE 为 2.50 厘米，作者参考轨迹在完全相同时间点、相同评测规则下为 2.71 厘米；采用覆盖更充分的真值插值，分别为 2.98 和 3.10 厘米。该次运行达到与仓库作者参考相近的精度水平。**

补充核验对象为前面讨论的 NTU-VIRAL `eee_01`。原来的 Retail Street 运行仍没有找到对应定位真值，不能将下列数值写成它的精度。

## 实测精度

误差均为平移 APE RMSE，越小越好；均进行刚体 SE(3) 对齐，尺度固定为 1、时间偏移为 0。IMU 估计位姿先按官方标定补偿到测量棱镜位置。作者结果使用的是作者提供的估计轨迹，并非另行运行 ROS 1 系统。

| 评测口径 | 本地 ROS 2 | 作者参考轨迹复算 | 两者相同的有效时间点数量 |
|---|---:|---:|---:|
| 作者仓库示例：evo 最近时间匹配，容差 0.01 秒 | **2.4980 cm** | 2.7109 cm | 1,337 |
| 官方教程方法：对原始真值线性插值，左右相邻测量均不超过 0.1 秒 | **2.9759 cm** | 3.1028 cm | 3,341 |

两份估计的匹配时间向量已逐项核对：第一种口径的 1,337 个时间点完全相同，第二种口径的 3,341 个时间点也完全相同。evo Python API 与命令行 ZIP 中的 RMSE 数值一致。

第一种口径纳入本地 3,983 个位姿中的 33.57%，匹配时段相对于首个位姿约为 61.82～378.62 秒，时间点分布不均；第二种口径纳入 83.88%，约为 46.81～383.02 秒。两套结果分别保留，不将稀疏匹配的较低误差当成整段每个时刻的误差。

主口径下，本地最大平移误差 7.63 厘米，平均 2.15 厘米；插值口径下，最大 11.05 厘米，平均 2.45 厘米。完整指标和每个匹配点的误差均已归档。

本地一次运行略低于作者参考，不足以证明移植本身提升了算法精度。也不能据此宣称复现了论文全部数据集、全部参数设置的结果。

## 数据来源与转换核对

- 原始数据来自 [NTU 官方数据页](https://ntu-aris.github.io/ntu_viral_dataset/) 指向的文件 `68133`，实际 ZIP 为 4,533,480,279 字节；MD5 与官方元数据 `5def8677063a4fbbf3e6c116bb8e685c` 相同，ZIP 解压 CRC 校验通过。
- ROS 2 派生 bag 保留 3,987 条水平 Ouster 点云、3,986 条左相机图像、153,347 条外置 IMU 和 6,616 条 Leica 测量位置，合计 167,936 条记录，录制跨度 398.682868 秒。
- 转换前后逐条比较传感器时间，图像和点云原始数据缓冲区全部一致；记录时间保持不变。只转换 ROS 1 序列化为 ROS 2 CDR，按 ROS 2 标准去掉 Header.seq。没有重采样、重标定或修改逐点时间。
- 原始测量真值与作者提供的 TUM 真值都是 6,616 条，最大位置分量差约 0.5 微米，最大时间差约 0.238 微秒，仅为文本精度舍入。
- 原始数据目录 `datasets/NTU_VIRAL_original/`、派生目录 `datasets/NTU_VIRAL_eee01_humble/`、下载来源、转换记录和校验值均保留。真值只参与离线评测，不输入里程计估计。

## 运行与完整性

运行目录：[20261020_114001](accuracy/eee_01/runs/20261020_114001/)。

| 检查项 | 结果 |
|---|---|
| ROS 2 源码 | Robotic-Developer-Road/FAST-LIVO2，humble 提交 `837b7bbc1431cb04cf936528e52c83c835efba8e`，沿用此前构建修复 |
| 参数 | 使用随源码提供的 NTU 及相机配置，仅更改输出序列名；没有为命中指标调参 |
| 回放 | 完整序列，0.5 倍速；运行约 824.65 秒，不能据此评价原速实时性 |
| 原生轨迹 | 3,983 个位姿，跨度 398.325021 秒，时间严格递增且值有限 |
| 最大位姿间隔 | 0.101472 秒，没有大于 0.15 秒的内部断档 |
| 四元数 | 最大模长偏差约 6.66×10⁻⁷ |
| 映射节点 | 正常退出；player、launch 返回值均为 0 |
| 视觉参与 | 3,982 次含原始特征的视觉处理日志 |
| 图像日志核对 | 全部 3,986 条均匹配 |
| IMU 日志核对 | 153,321 条匹配；未匹配的 26 条全部在首次 IMU 回调日志之前，中途和尾部未发现缺口 |

IMU 回调在首次 LiDAR 到达前会直接返回，因此上述启动阶段日志缺口与代码的初始化门控相符。PointCloud2 回调没有逐帧日志，不能据此声称每条 LiDAR 数据都被消费。

运行阶段和映射节点都没有 ERROR。完整 launch 日志含一条收尾记录：映射节点正常退出后，关闭相机参数服务 `parameter_blackboard` 时收到 SIGINT，launch 将其记为退出码 -2 的 ERROR。该条已单独分类保留，不将“整份日志零 ERROR”作为本次结论。
