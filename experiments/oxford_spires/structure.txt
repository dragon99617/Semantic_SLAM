## Image files
- Format: JPEG
- Resolution: 1440 × 1080
- Camera model: `OPENCV_FISHEYE` (FoV 126° ×92.4°)
- Filename: Unix timestamp in seconds with nanosecond precision, e.g. `1710230400.123456789.jpg`
- Three cameras: `cam0` (front), `cam1` (left), `cam2` (right)

## LiDAR files

- Format: PCD (binary or ASCII)
- Sensor: Hesai QT64 (64 channels, 10 Hz, 60 m range)

### Raw clouds (`raw/lidar-clouds/`)
- Filename: `<timestamp>.pcd`, e.g. `1710230400.123456789.pcd`
- Points are in the **lidar frame**

### Undistorted clouds (`processed/vilens-slam/undist-clouds/`)
- Filename: `cloud_<sec>_<nsec>.pcd`, e.g. `cloud_1710230400_123456789.pcd`
  - `sec`: 10-digit Unix timestamp seconds
  - `nsec`: 9-digit nanoseconds
- Points are in the **base frame** (defined [here](https://github.com/ori-drs/oxford_spires_dataset/blob/main/configs/sensor.yaml#L37))

## Trajectory files

Two formats are used across the codebase:

### TUM format
```
timestamp tx ty tz qx qy qz qw
```
Standard [TUM RGB-D format](https://vision.in.tum.de/data/datasets/rgbd-dataset/file_formats). Read/written via `oxspires_tools.trajectory.file_interfaces.TumTrajReader/Writer`.

### VILENS SLAM format (`poses.csv`)
CSV with columns `timestamp, tx, ty, tz, qx, qy, qz, qw`. Read/written via `oxspires_tools.trajectory.file_interfaces.VilensSlamTrajReader/Writer`.


## Notes
### ROS message timestamps
Rhere are two distinct timestamps associated with a ROS message in the ROSbag:

- **Sensor Time (preferred)** 
  The time when the data was actually captured by the sensor. This is the true acquisition time.

- **ROS Receive Time** 
  The time when the message is read from the bag or received by the system. This may include transport and processing delays.

#### Example

```python
import rosbag

bag = rosbag.Bag(bag_path)

for topic, msg, t in bag.read_messages(topics=[topic_name]):
    receive_time = t                 # when ROS reads the message
    sensor_time = msg.header.stamp   # actual sensor capture time
